Design for
the professional.

The existing interface was visually polished, but it needed a stronger connection to the business requirements and the tasks people performed in the product.

I worked within the existing brand identity, refining the palette, chart choices, and layout. The aim was clearer data and a flexible interface that could accommodate Japanese and English.

Align early.
Hand off clearly.

I owned wireframes, user flows, and design handoff, supporting the product manager with requirements gathering to make project decisions faster and smoother. Rough sketches in FigJam and Miro helped align stakeholders before high-fidelity design.

I guided four junior designers through design reviews and ongoing support. For frontend engineers, I explained design intent, documented component states and interactions, and worked hands-on with CSS to reduce handoff time across time zones.

Standardize the core. Extend with evidence.

Product wanted complex, fully customizable components for client edge cases. Engineering warned that repeating these patterns across every module would delay delivery and add technical debt.

My screen audit showed that roughly 40% of workflows could use 5–8 core components. I drove a phased core-vs-extension model based on that evidence.

Shared core
Use standard design tokens and core components for the first release, keeping the interface consistent across modules.
Extensions
Add specialized components only when post-launch usage data demonstrates clear business value.
Trade-off
Defer edge-case customization to protect delivery speed and maintainability, while leaving a path for evidence-backed extensions.

Outcome: Frontend delivery time fell by approximately 30%, and key features shipped one month ahead of schedule. Shared governance kept the UI consistent without blocking product teams.

Test before
committing to build.

When users were available, I clarified the target audience, increased interview frequency, and dedicated more time to research.

For features without a clear best practice, we used Figma prototypes or lightweight frontend-only builds to test with users before committing to development. Not every feature could be tested, so the approach reflected the evidence available.
